两段视频已确认为**最终素材**，不再重录。本文记录素材参数、四个标定像素点、最终统计结果和复现命令，
供自己和协作者（UI / UE5）对照。字段口径见 [`realtime_data_contract.md`](realtime_data_contract.md)，

## 2. 四个标定像素点（已点好，不用再点）

点选顺序统一为 **左柱脚 → 右柱脚 → 右门框底 → 左门框底**，都是建筑自身的角点，不摆标记物。
地面梯形 `[[0,0],[4.47,0],[3.87,2.13],[0.6,2.13]]` 与门洞计数线 `p1=[0.6,2.13] p2=[3.87,2.13]`
两段相同（同一组实测尺寸），只有像素点不同。

| | `image_points` |
|---|---|
| **A** | `[[440,910],[1350,886],[1040,765],[560,765]]` |
| **B** | `[[270,665],[930,695],[800,555],[400,555]]` |

⚠️ **像素坐标与分辨率绑定**：A 的点是按 1920×1080 读的，B 是按 1280×720 读的。
若转码、裁剪或换素材，必须重新标定，否则网格会整体错位。
重新标定用 `tools/calibrate_homography.py --entrance-geometry 4.47,3.27,2.13`。

## 3. 复现命令

```bash
# 0) 把两段素材放到 data/input/，改成约定名
#    video_a_1080p.mp4 / video_b_720p.mp4

# 1) 跑 A（已标定，直接出结果）
python3 -m src.run_pipeline --config configs/final_a_1080p.json

# 2) 跑 B
python3 -m src.run_pipeline --config configs/final_b_720p.json
```

配置里的相对路径按**配置文件所在目录**解析（`../data/input/`、`../out/`），
所以从项目根目录执行上面的命令即可。`--video` / `--out` 可在命令行临时覆盖。

每段会在 `out/entrance_a|b/` 产出 9 个文件：
`npc_tracks.json`（UE5）、`realtime.json`（UI）、`analytics.json`、`tracks.json`、`tracks.csv`、
`heatmap.png`、`calibration_check.png`、`annotated.mp4`、`dashboard.html`。

## 4. 最终统计结果（已加计数防抖）

`counters` 的防抖阈值 `debounce_sec=0.5` / `min_travel_m=0.15` 已写入两份配置。
修防抖前，脚点在门线附近抖动会被反复计数，进出人次高估 60%~80%；下表为修正后的**最终口径**。

| 指标 | **A** | **B** |
|---|---|---|
| 累计人数 | 58 | 34 |
| 进店 / 出店 | **74 / 37** | **22 / 8** |
| 净流入 | +37 | +14 |
| 峰值同框 | 26 人 @ 3.87 s | 18 人 @ 25.10 s |
| 平均同框 | 18.07 人 | 13.06 人 |
| 人均停留 | 10.05 s | 12.18 s |
| 门前平台到访 / 区域峰值 | 30 人 / 7 人 | 10 人 / 3 人 |
| NPC 轨迹数 | 58 | 34 |

三处口径已核对一致：`analytics.json` = `realtime.json` 末帧 = 事件流计数 =
`annotated.mp4` 画面上计数线显示的 `door in:74 out:37`（A）。

> 报告口径：以「累计人数 / 进 / 出 / 峰值同框 / 人均停留」为准。
> 防抖只修正穿线判定，**累计人数、峰值、停留、热力图不受影响**。

## 6. 已知局限（素材已定稿，不重录）

两段画面都能看到雨棚底面，属于**站立平视**机位，不是约定的抬高俯拍（2.5~4 m / 俯角 25°~45°）。
画面覆盖范围远大于 `4.47 × 2.13 m` 的标定平台，因此：

- A 约 **84%**、B 约 **92%** 的脚点落在标定梯形之外（透视外推）；
- **不受影响**：累计人数、进出人次、峰值同框、人均停留（只看检测框与穿线）；
- **受影响**：框外人员的地面位置、速度 m/s、UE5 里的绝对走位、热力图只统计真正踩在平台上的人
  （A 约 16%、B 约 8%）、门前区域占用；
- 拥挤时轨迹拼接仍可能漏拼，累计人数可能略偏高（估计 5%~10%），方向不会错。

这些是机位带来的固有误差，不通过调参消除。演示与报告以人数类指标为主即可；
UE5 里 NPC 走位按 `npc_tracks.json` 播放，平台外的点会落在场景地面之外，建模时把门前地面铺大一圈可缓解。
